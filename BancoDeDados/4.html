As Famílias da Linguagem SQL

Classificação Oficial

A linguagem SQL é dividida em subconjuntos especializados de acordo com o objetivo da instrução:

DDL

Data Definition Language

Comandos que criam, alteram e destroem a estrutura do banco de dados (tabelas, índices, esquemas).

CREATE • ALTER • DROP
TRUNCATE • RENAME
Mexe no esqueleto (metadados).
DML (e DQL)

Data Manipulation Language

Comandos que inserem, consultam, atualizam e excluem os dados gravados dentro das tabelas.

SELECT • INSERT
UPDATE • DELETE
Mexe no conteúdo (tuplas/linhas).
DCL & TCL

Data Control & Transaction

Comandos de segurança de acesso (permissões de usuários) e controle transacional.

GRANT • REVOKE (DCL)
COMMIT • ROLLBACK (TCL)
Mexe na segurança e integridade.
Construindo a estrutura das tabelas Módulo 4.1 — DDL em Ação →
Módulo 4.1 • Definição de Estruturas

DDL em Ação: CREATE, ALTER, DROP e TRUNCATE

Metadados
CREATE TABLE: Cria a tabela com tipos de dados, Chave Primária (PK) e restrições.
ALTER TABLE: Altera a estrutura sem apagar os dados existentes (adiciona colunas, muda tipos ou adiciona FKs).
DROP TABLE: Exclui a tabela e todos os seus dados definitivamente do disco. A estrutura deixa de existir!
TRUNCATE TABLE: Esvazia rapidamente todas as linhas, mas mantém a estrutura e as colunas intactas.
-- Exemplos Práticos de DDL
CREATE TABLE produtos (
  id_prod INT PRIMARY KEY,
  nome VARCHAR(100) NOT NULL,
  preco NUMERIC(10,2) CHECK (preco > 0)
);

ALTER TABLE produtos
  ADD COLUMN estoque INT DEFAULT 0;

TRUNCATE TABLE logs_acesso; -- Limpa linhas em milissegundos

Módulo 4.1 • Manipulação de Dados (Parte 1)

DML em Ação: A Arte do INSERT e do SELECT

Gravação & Consulta
INSERT INTO: O Comando de Escrita Grava novas linhas na tabela. Recomenda-se explicitar sempre as colunas de destino para evitar erros caso a ordem mude no futuro. Suporta inserção múltipla (*bulk*).
SELECT: O Comando Mais Poderoso do SQL Recupera dados filtrados, ordenados e agregados.
SELECT colunas
FROM tabela
WHERE condicao_filtro
ORDER BY coluna DESC
LIMIT 10;
-- Exemplos Práticos de INSERT e SELECT
INSERT INTO clientes (id, nome, cidade)
VALUES
  (1, 'Ana Lima', 'São Paulo'),
  (2, 'Bruno Dias', 'Curitiba');

-- Consulta com filtro e projeção limpa
SELECT nome, cidade
FROM clientes
WHERE cidade = 'São Paulo';
Cuidado com os comandos que alteram e deletam dados! Módulo 4.1 — DML: UPDATE e DELETE →
Módulo 4.1 • Manipulação de Dados (Parte 2)

UPDATE e DELETE: O Perigo Mortal sem WHERE!

Cuidado Crítico
UPDATE: Modifica Linhas Existentes Altera o valor de uma ou mais colunas nas linhas que satisfazem o critério do WHERE.
DELETE: Remove Linhas Selecionadas Remove apenas os registros que cumprem a condição especificada.
⚠️ A Maior Tragédia de um Programador: Se você executar um UPDATE ou DELETE sem a cláusula WHERE, o comando afetará TODAS AS LINHAS DA TABELA de uma só vez!
-- O Certo vs O Erro Fatal
-- ❌ ERRO FATAL: Zera o salário de TODOS na empresa!
UPDATE funcionarios SET salario = 0;

-- ✅ FORMA SEGURA: Com WHERE filtrando o alvo exato
UPDATE funcionarios
SET salario = 4500.00
WHERE id_funcionario = 101;

DELETE FROM clientes
WHERE status_cadastro = 'cancelado';

Módulo 4.1 • Segurança e Integridade

DCL e TCL: Controle de Acesso e Transações

Permissões & Controle
DCL (Data Control Language)
GRANT: Conceder Permissões

Dá direitos a um usuário específico para ler, gravar ou modificar tabelas.

GRANT SELECT, INSERT ON pedidos TO operador_caixa;
REVOKE: Revogar Permissões

Remove permissões concedidas anteriormente.

REVOKE DELETE ON pedidos FROM operador_caixa;
TCL (Transaction Control Language)
COMMIT: Confirmação Definitiva

Grava todas as operações da transação permanentemente no banco.

ROLLBACK: Cancelamento & Reversão

Desfaz tudo o que foi feito desde o último BEGIN TRANSACTION, restaurando o estado original intacto.

🛡️ Segurança em Produção: Sempre abra transações antes de manutenções manuais em tabelas corporativas!

Views: Visões Virtuais para Simplificação e Segurança

CREATE VIEW

Uma View é uma tabela virtual cujo conteúdo é definido por uma consulta SQL pré-compilada. Ela não duplica os dados no disco: toda vez que você consulta a View, o banco executa o SELECT subjacente em tempo real.

1. Segurança de Colunas (LGPD) Você pode dar acesso a uma View que exibe apenas nome e e-mail, ocultando colunas sensíveis como CPF, senha ou salário.
2. Simplificação de Consultas Complexas Em vez de escrever um JOIN de 5 tabelas toda semana, você encapsula tudo em uma View e consulta como se fosse uma tabela simples: SELECT * FROM vw_vendas_consolidadas;.
-- Criando uma View Segura
CREATE VIEW vw_equipe_publica AS
SELECT
  id_funcionario,
  nome_completo,
  cargo,
  departamento
  -- coluna 'salario' foi omitida por sigilo!
FROM funcionarios
WHERE status_ativo = TRUE;

-- O analista consulta a View normalmente:
SELECT * FROM vw_equipe_publica;

Triggers: Gatilhos Automáticos no Servidor

Event-Driven

Um Trigger (Gatilho) é um procedimento armazenado que é executado de forma automática e transparente quando um evento de modificação (INSERT, UPDATE ou DELETE) ocorre na tabela.

Quando o Gatilho Dispara?
• BEFORE: Executado antes do dado ser gravado. Excelente para validações e preenchimento de campos automáticos.
• AFTER: Executado depois do dado ser gravado com sucesso. Perfeito para logs de auditoria e sincronização.
⭐ As Variáveis Mágicas: O SGBD disponibiliza NEW (o novo valor que está entrando) e OLD (o valor antigo que estava gravado na linha antes do update).
-- Estrutura Conceitual de um Trigger
CREATE TRIGGER tg_auditar_salario
AFTER UPDATE ON funcionarios
FOR EACH ROW
BEGIN
  INSERT INTO log_auditoria (
    id_func, salario_antigo, salario_novo, data_alt
  ) VALUES (
    OLD.id, OLD.salario, NEW.salario, NOW()
  );
END;

Stored Procedures: Procedimentos Armazenados

CALL procedure()

Uma Stored Procedure é um bloco de código contendo uma sequência de comandos lógicos e transações, compilado e armazenado diretamente no servidor de banco de dados.

Redução Drástica de Tráfego de Rede Em vez de enviar 10 comandos SQL via internet entre o app e o banco, a aplicação envia apenas uma chamada: CALL sp_fechar_caixa(12);.
Parâmetros Flexíveis Aceita parâmetros IN (dados que entram), OUT (valores retornados) e INOUT.
Segurança Centralizada O programador do aplicativo não precisa de permissão direta nas tabelas; ele só precisa de permissão para executar a procedure!
-- Exemplo no MySQL / PostgreSQL
CREATE PROCEDURE sp_dar_desconto(
  IN p_id_prod INT,
  IN p_porcentagem DECIMAL(5,2)
)
BEGIN
  UPDATE produtos
  SET preco = preco * (1 - (p_porcentagem / 100))
  WHERE id = p_id_prod;
END;

-- Executando a procedure:
CALL sp_dar_desconto(101, 15.0);

Stored Procedures vs Functions (UDFs)

Não Confunda!
Característica Stored Procedure User-Defined Function (UDF)
Propósito Principal Executar ações de negócios, fluxos e rotinas pesadas Calcular e transformar valores (fórmulas e lógicas)
Retorno Obrigatório Opcional (pode não retornar nada ou usar parâmetros OUT) Obrigatório (sempre retorna exatamente um valor ou tabela)
Uso Dentro do SELECT ❌ Não pode ser chamada dentro de SELECT ✅ Pode ser usada diretamente no SELECT fn_calcular(x)
Como é Chamada CALL sp_processar(); ou EXEC SELECT fn_imposto(salario) FROM...
💡 Resumo Didático: Se você quer calcular o imposto de renda de uma linha, use uma Function; se você quer processar o pagamento de 1.000 funcionários e emitir notas, use uma Stored Procedure!

PL/SQL & PL/pgSQL: Fundamentos Procedimentais

Lógica no Banco

O SQL padrão é uma linguagem declarativa: você diz o que quer, mas não tem variáveis, laços de repetição (LOOP) nem tratamento de erros.

O PL/SQL (Oracle) e o PL/pgSQL (Postgres) estendem o SQL adicionando o poder de uma linguagem de programação procedural completa.

O Esqueleto Universal de um Bloco PL/SQL:
• DECLARE: Declaração de variáveis, constantes e cursores.
• BEGIN: Início do código executável (comandos, IF, loops).
• EXCEPTION: Captura e tratamento de erros (ex: divisão por zero).
• END; Fim do bloco.
-- Bloco Anônimo PL/SQL
DECLARE
  v_limite NUMBER(10,2) := 5000.00;
  v_saldo NUMBER(10,2);
BEGIN
  SELECT saldo INTO v_saldo FROM contas WHERE id = 1;

  IF v_saldo > v_limite THEN
    DBMS_OUTPUT.PUT_LINE('Cliente categoria Platinum');
  ELSE
    DBMS_OUTPUT.PUT_LINE('Cliente categoria Standard');
  END IF;
END;

Estruturas de Controle e Cursores em PL/SQL

Loops & Ponteiros
O que é um Cursor? O SQL trabalha tradicionalmente com conjuntos inteiros de dados. Um Cursor é um ponteiro de memória que permite ao desenvolvedor percorrer o resultado de um SELECT linha por linha individualmente.
Ciclo de Vida do Cursor:
DECLARE cursor ➔ OPEN (aloca memória) ➔ FETCH (carrega próxima linha) ➔ CLOSE (libera memória).
Laços de Repetição: Suporta WHILE, FOR loop e LOOP simples com cláusula EXIT WHEN.
-- Iterando com Cursor FOR Loop
DECLARE
  CURSOR c_pedidos IS
    SELECT id_pedido, valor FROM pedidos WHERE status = 'pendente';
BEGIN
  -- O FOR abre, faz fetch e fecha o cursor automaticamente
  FOR r_ped IN c_pedidos LOOP
    sp_notificar_financeiro(r_ped.id_pedido, r_ped.valor);
  END LOOP;
END;

Módulo 4.3 • A Quebra do Padrão SQL

Linguagens de Consulta no Mundo NoSQL

Além do Relacional

Como vimos na Aula 2, o ecossistema NoSQL não possui tabelas rígidas. Por isso, cada família possui sua própria forma nativa de consulta:

DOCUMENTOS

MongoDB (MQL)

Consultas baseadas em objetos e filtros JSON/BSON utilizando métodos encadeados como find() e aggregate().

db.users.find({ idade: { $gt: 18 } })
CHAVE-VALOR

Redis (Comandos)

Comandos diretos e atômicos em memória RAM para leitura e escrita em microssegundos baseados em chaves de busca.

SET session:101 "token" EX 3600
GRAFOS

Neo4j (Cypher)

Linguagem declarativa baseada em arte ASCII que desenha padrões visuais de conexões entre nós e arestas.

MATCH (u)-[:SEGUE]->(f) RETURN f
Como o MongoDB substitui os comandos tradicionais do SQL? MQL: MongoDB vs SQL →
Módulo 4.3 • De-Para Tecnológico

MongoDB Query Language (MQL) vs SQL

Comparativo Direto
Operação SQL Relacional Tradicional MongoDB (MQL em JSON)
Inserir Registro INSERT INTO clientes (nome, cidade) VALUES ('Carlos', 'SP'); db.clientes.insertOne({ nome: "Carlos", cidade: "SP" });
Consultar Todos SELECT * FROM clientes; db.clientes.find({});
Filtrar (WHERE) SELECT * FROM clientes WHERE cidade = 'SP'; db.clientes.find({ cidade: "SP" });
Atualizar Campo UPDATE clientes SET status = 'ativo' WHERE id = 10; db.clientes.updateOne({ _id: 10 }, { $set: { status: "ativo" } });
Excluir Linha DELETE FROM clientes WHERE id = 10; db.clientes.deleteOne({ _id: 10 });
⭐ Perceba a analogia: A Tabela no SQL vira uma Coleção (Collection) no MongoDB; a Linha/Tupla vira um Documento JSON!

Redis & Grafos (Cypher) na Prática

Alta Performance
Comandos Rápidos no Redis

Ideal para guardar sessões que expiram sozinhas e contadores:

# Grava sessão com expiração de 30 minutos
SET sessao:usr_99 "token_xyz" EX 1800
# Busca o valor na memória RAM
GET sessao:usr_99
# Incrementa contador atômico (evita colisão)
INCR visualizacoes:produto_42
Consulta em Grafos (Cypher / Neo4j)

Navegando entre amigos de amigos sem precisar de 5 JOINs:

// Busca amigos em comum de Carlos
MATCH (c:Pessoa {nome: 'Carlos'})-[:AMIGO_DE]->(a:Pessoa)
RETURN a.nome;

// Recomenda produtos comprados por amigos
MATCH (c)-[:AMIGO_DE]->(a)-[:COMPROU]->(p:Produto)
RETURN p.titulo, COUNT(p) ORDER BY COUNT(p) DESC;

Gabarito Oficial e Guia Pedagógico

Questão 1: Família DDL

Resposta Correta: O comando ALTER TABLE (assim como CREATE, DROP e TRUNCATE) define ou modifica a estrutura dos metadados da tabela, pertencendo à DDL.

Questão 2: Variáveis NEW e OLD em Triggers

Resposta Correta: Em um comando UPDATE, a variável OLD contém os valores anteriores da linha e a variável NEW contém os novos valores que foram enviados.

Questão 3: Natureza das Views

Resposta Correta: São tabelas virtuais baseadas em consultas SELECT que não duplicam fisicamente os dados no disco, mas filtram colunas e simplificam consultas.

Questão 4: Stored Procedures vs Functions

Resposta Correta: Stored Procedures são chamadas com CALL e não podem ser invocadas dentro de uma expressão SELECT comum, enquanto Functions (UDFs) retornam um valor e podem ser usadas dentro de SELECTs.

Questão 5: Equivalente NoSQL do SELECT *

Resposta Correta: No MongoDB, db.colecao.find({}) com objeto de filtro vazio retorna todos os documentos, correspondendo ao SELECT * FROM tabela;.

Guia de Excelência Técnica

As 7 Leis do Desenvolvedor de Banco de Dados

Boas Práticas
1.
WHERE é sagrado: Nunca rode UPDATE ou DELETE sem filtro em ambiente de produção.
2.
Transações sempre: Abra BEGIN antes de alterar dados manuais e só faça COMMIT após checar.
3.
Proteja com Views: Exponha apenas o necessário para relatórios e APIs, blindando dados confidenciais.
4.
Triggers com parcimônia: Use gatilhos para auditoria e logs; evite colocar regras de negócio complexas ocultas em triggers.
5.
Aproveite Stored Procedures: Reduza o tráfego de rede e garanta que regras críticas rodem compiladas no servidor.
6.
Adote o NoSQL onde ele brilha: Use Redis para cache/sessões e MongoDB para documentos e logs flexíveis.
7.
Documente e Comente: Scripts legíveis salvam equipes. Explique o "porquê" das decisões nos comentários de cabeçalho!
