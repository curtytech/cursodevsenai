O que são Dados? Os blocos de construção

Fatos Brutos

Um dado é um elemento bruto: um número, uma palavra, um símbolo ou uma data coletada sem contexto imediato.

Atenção: Isoladamente, um dado não transmite uma mensagem completa e não permite tomar uma decisão segura.

  • Exemplos soltos: 38,5, "Silva", "Curitiba", 120
  • O que significa "38,5"? É o preço de um item? A temperatura? Ou o número de um calçado?

O que é um Banco de Dados e para que serve?

Database

Um Banco de Dados é uma coleção organizada, estruturada e integrada de dados, armazenada digitalmente de modo a permitir buscas ágeis, atualizações seguras e consultas simultâneas.

Por que não guardar tudo em cadernos de papel?

⚡ Alta Velocidade Busca 1 cliente entre 5 milhões em menos de 0,02 segundos.

Banco de Dados vs SGBD vs Sistema de Informação

Não Confunda!
Camada 1: Usuário

Sistema de Informação

É a interface com telas, botões, formulários e relatórios que os funcionários e clientes enxergam e clicam.

Exemplos: App do Banco, Tela de Caixa do Mercado, Portal do Aluno.
Pede dados para o motor gerenciador.
Camada 2: O Motor

SGBD (DBMS)

Sistema Gerenciador de Banco de Dados: O software inteligente que processa comandos, garante a segurança e faz a leitura/escrita física.

PostgreSQL, MySQL, SQL Server, Oracle, SQLite.
Controla, protege e localiza os registros.
Camada 3: Armazém

Banco de Dados (Dados)

O repositório em disco (SSD/HD/Nuvem) onde os arquivos físicos de tabelas, índices e logs residem gravados em bytes.

Analogia: Se o Banco é o arquivo de gavetas, o SGBD é o arquivista que organiza e tranca as gavetas.
Onde a matéria-prima fica gravada.

O Coração da Empresa: O Cadastro de Clientes

TechVarejo

Nenhuma empresa sobrevive sem saber quem compra seus produtos, como contatá-los e onde eles moram.

Quais informações compõem um cadastro sadio?

✓ Identificador Único: Um código numérico para nunca confundir clientes.
✓ Nome Completo: Grafia padronizada sem abreviações confusas.
✓ Canais de Contato: E-mail válido e telefone com DDD.
✓ Localização & Data: Cidade para planejar frete e data de adesão.
O Risco de Cadastros Duplicados e Inconsistentes
  • • Enviar duas faturas ou cupons repetidos para a mesma pessoa.
  • • Mercadoria devolvida porque o endereço continha erros de digitação.
  • • Estatísticas distorcidas: achar que tem 10.000 clientes quando 3.000 são cópias repetidas da mesma pessoa.

Módulo 4 • Identidade Única

A Chave Primária (Primary Key — PK)

Regra de Ouro

O que é a Chave Primária?

É um campo especial (ou conjunto de campos) cujo valor é estritamente único para cada linha da tabela. Ela funciona como o "CPF" ou "RG" do registro.

1.
Não pode se repetir: Não existem dois registros com a mesma chave.
2.
Não pode ser nula (NOT NULL): Todo registro obrigatoriamente tem uma chave.
3.
Por que não usar o Nome? Existem milhares de "José da Silva" no Brasil (homônimos!). O nome causaria confusão fatal em contas bancárias ou notas fiscais.
Garantia de Identidade
id_cliente: 101 Carlos Mendes (São Paulo)
PK ÚNICA
id_cliente: 102 Carlos Mendes (Curitiba - Homônimo!)
PK ÚNICA
💡 Dica: Em sistemas reais, a chave primária costuma ser um número auto-incremental gerado automaticamente pelo SGBD (1, 2, 3...).

Módulo 5 • Qualidade da Informação

Tratamento e Limpeza de Dados (Data Cleansing)

Higienização

Tratar dados significa identificar e corrigir erros, incompletudes, inconsistências e duplicações antes de disponibilizar as informações para o negócio.

Os 4 Pilares da Higienização:

1. Padronização: Ex: Cidade escrita como "SP", "S. Paulo", "sao paulo" vira sempre "São Paulo".
2. Desduplicação: Fusão de registros repetidos com o mesmo CPF ou e-mail.
3. Validação de Obrigatórios: Garantir que nenhum pedido seja emitido sem telefone ou e-mail de contato.
4. Formatação Uniforme: Datas no padrão AAAA-MM-DD e telefones com código de área (DDD).
Impacto Direto na Empresa
Sem Tratamento:

Campanhas de marketing desperdiçam verba enviando 3 e-mails para a mesma pessoa; clientes não recebem SMS com código de entrega.

Com Tratamento Profissional:

Base confiável, relatórios 100% fieis à realidade e auditorias financeiras sem divergências.

Como os Dados Vivem: Armazenamento e SQL

Lógico vs Físico

A Dupla Natureza do Banco

Visão Lógica (Para Humanos e Desenvolvedores): Tabelas com nomes amigáveis, linhas, colunas, chaves primárias e relacionamentos compreensíveis.
Armazenamento Físico (Na Máquina): Blocos de bytes gravados em discos SSD de servidores locais (On-Premises) ou servidores na Nuvem (Cloud: AWS, Azure, Google Cloud).
🔒 Segurança e Backup: Cópias periódicas automáticas (backups) garantem que se o servidor queimar, nenhum dado de cliente seja perdido.
SQL: Structured Query Language O idioma universal

Como os programadores conversam com o SGBD para pedir informações:

SELECT * FROM clientes WHERE cidade = 'Curitiba'; -> "Busque todos os clientes que moram em Curitiba"
INSERT INTO clientes ... (Cadastrar novo)
UPDATE clientes SET ... (Atualizar dados)
SQL é padrão internacional desde os anos 1970 até hoje!

Módulo 9 • Responsabilidade Social e Legal

Ética, Privacidade e Lei Geral de Proteção de Dados (LGPD)

Lei 13.709
1. Princípio da Necessidade: Colete apenas o que for estritamente útil para a operação. (Uma loja de roupas precisa perguntar a religião ou tipo sanguíneo do cliente? Não!).
2. Finalidade e Transparência: O titular do dado tem o direito de saber exatamente para que seus dados serão usados e onde ficarão guardados.
3. Controle de Acesso & Confidencialidade: Nem todo funcionário pode ver tudo. Apenas o setor financeiro deve ter acesso a dados de cartão de crédito.
❌ Más Práticas (Risco de Multa)
  • • Vender lista de e-mails para outras empresas.
  • • Deixar senhas salvas em texto puro sem criptografia.
  • • Deixar relatórios de clientes impressos jogados na mesa.
✅ Boas Práticas (Cultura Segura)
  • • Consentimento explícito ao cadastrar.
  • • Autenticação em 2 fatores para acessar o banco.
  • • Opção para o cliente solicitar a exclusão de seus dados.

Exclusivo para o Docente

Gabarito Oficial e Guia Pedagógico

Questão 1: Diferença entre Dado e Informação

Resposta Correta: O dado é o fato bruto desprovido de contexto (ex: 38,5); a informação é o dado processado e contextualizado que transmite um significado claro (ex: temperatura corporal indicando febre).

Questão 2: Papel do SGBD

Resposta Correta: O SGBD é o software gerenciador que controla o acesso, a segurança, o processamento de consultas e a integridade física dos dados gravados em disco.

Questão 3: Finalidade da Chave Primária (PK)

Resposta Correta: Identificar cada registro de forma única e exclusiva na tabela, garantindo que não haja duplicidade nem confusão entre clientes diferentes (inclusive homônimos).

Questão 4: Planilha vs Banco de Dados

Resposta Correta: Bancos de dados oferecem suporte a múltiplos usuários simultâneos com alto desempenho, regras estritas de integridade e segurança robusta contra corrupção de arquivos.

Questão 5: Princípio da Necessidade na LGPD

Resposta Correta: A organização deve coletar estritamente os dados essenciais para atingir sua finalidade de negócio, evitando coletar dados desnecessários ou sensíveis sem justificativa legal.
