Iniciativa no Ambiente Profissional

Módulo 5

📌 O que é iniciativa?

É a capacidade de agir de forma proativa — identificar o que precisa ser feito e fazer, sem esperar que alguém diga. No ambiente de TI, significa propor soluções antes que os problemas se agravem.

👁️

Identificar

Perceber problemas e oportunidades antes dos outros

⚡

Agir

Tomar ações sem esperar aprovação para o óbvio

🏆

Gerar valor

Transformar observações em resultados concretos

💡 Exemplo: Um dev percebe que o sistema lentifica às 18h. Sem ser pedido, analisa os logs, encontra a causa e abre um chamado com a solução — antes do cliente reclamar.

Proativo vs. Reativo

✅ Profissional proativo

→ Antecipa falhas antes do prazo

→ Sugere melhorias sem ser pedido

→ Busca informações por conta própria

→ Comunica riscos cedo

❌ Profissional reativo

→ Espera o problema explodir

→ Age somente quando é cobrado

→ Sempre "não sabia"

→ Perde prazos previsíveis

Fundamentos de User Experience (UX)

Módulo 6

O que é UX?

User Experience (Experiência do Usuário) é a percepção que uma pessoa tem ao usar um produto ou sistema — se é fácil, agradável, eficiente e satisfatório.

Usabilidade

Fácil de usar e aprender

Facilidade

Tarefas rápidas, sem obstáculos

Organização

Informações bem estruturadas

Acessibilidade

Inclusivo para todos os usuários

Satisfação

Usuário sente prazer ao usar

Boa UX vs. Má UX

✅ Boa UX — App de banco

  • • Menu claro com 4 opções principais
  • • Transferência em 3 cliques
  • • Confirmação com feedback visual
  • • Texto legível em qualquer tela

❌ Má UX — Portal gov. antigo

  • • 15 menus diferentes sem hierarquia
  • • Formulário perde dados ao errar
  • • Mensagem de erro genérica
  • • Não funciona no celular
🎯 Regra de ouro:
O sistema deve se adaptar ao usuário — não o contrário!

Conectividade e Interoperabilidade

Módulo 7
🔌

Conectividade

É a capacidade de sistemas, dispositivos ou redes se comunicarem entre si — seja por internet, Wi-Fi, Bluetooth ou protocolos específicos.

Ex: Seu celular conectando ao sistema do banco para verificar saldo.
🔗

Interoperabilidade

É a capacidade de diferentes sistemas trocarem e usarem informações entre si, mesmo que tenham sido criados por empresas ou tecnologias diferentes.

Ex: Sistema de RH enviando dados de salário diretamente para o sistema contábil.

Analogia simples

📱 App Banco
HTTP/REST ←→ Conectividade
🏦 Banco Central
PIX API ←→ Interoperabilidade
🏧 Outro Banco

Sistemas integrados

🛒 E-commerce

Site ↔ Estoque ↔ Pagamento ↔ Entrega ↔ Nota Fiscal

🏥 Hospital

Prontuário ↔ Laboratório ↔ Farmácia ↔ Convênio

🚚 Logística

ERP ↔ Transportadora ↔ Rastreio ↔ Cliente

🌟 Resultado

Sistemas integrados evitam digitação manual, erros e retrabalho.

APIs — A Cola entre os Sistemas

API (Application Programming Interface) é um conjunto de regras que permite que dois sistemas se comuniquem — como um garçom que leva o pedido da mesa até a cozinha e traz o resultado.

Técnicas de Modelagem

Módulo 8

O que é modelagem?

Modelagem é a representação visual de um sistema, processo ou estrutura antes de construí-lo — como a planta de uma casa antes da obra. Reduz erros, alinha expectativas e facilita a comunicação.

🗺️

Visão geral

Enxergar o sistema completo antes de codificar

🤝

Comunicação

Cliente, dev e gestor falam a mesma língua

💰

Redução de custo

Corrigir no modelo é 10x mais barato que no código

Exemplo: Fluxograma de Login

Quando modelar?

📋 Antes de qualquer linha de código
🔄 Ao refatorar sistemas existentes
🤝 Ao integrar dois sistemas diferentes
📢 Ao apresentar uma solução ao cliente
💡 "Horas de modelagem evitam dias de retrabalho."
🛠️

Linguagem UML

Módulo 8.2

O que é UML?

UML (Unified Modeling Language) é uma linguagem padronizada de modelagem visual usada para representar sistemas de software de forma que qualquer desenvolvedor no mundo possa entender.

Modelagem de Sistemas — Definição e Tipos

Módulos 9 / 9.1 / 9.2

O que é Modelagem de Sistemas?

É o processo de criar representações abstratas de um sistema para compreender seus requisitos, estrutura e comportamento — antes e durante o desenvolvimento de software.

Tipos de Modelagem

⚙️

Processos

Fluxo das atividades e tarefas do sistema. Usa fluxogramas e BPMN.

Ex: Fluxo de pedido
🗄️

Dados

Estrutura das informações armazenadas. Usa DER e diagrama de classes.

Ex: Tabelas do BD
🎯

Funcional

O que o sistema faz — funções, entradas e saídas. Usa casos de uso.

Ex: Caso de uso
🏛️

Estrutural

Componentes, classes e relacionamentos estáticos do sistema.

Ex: Diagrama de classes
🔄

Comportamental

Como o sistema reage a eventos ao longo do tempo.

Ex: Diagrama de sequência
🖥️

Interfaces

Protótipos e wireframes das telas — conecta UX à modelagem.

Ex: Wireframe Figma

Relação com o desenvolvimento

1 Levantar requisitos
↓
2 Modelar o sistema
↓
3 Validar com o cliente
↓
4 Desenvolver com segurança
💡 Modelar reduz riscos e garante que todos entendam o mesmo sistema.

Características de uma Boa Modelagem

Módulo 9.3
C

Clareza

O modelo deve ser fácil de entender por qualquer membro da equipe, sem ambiguidades.

O

Organização

Elementos agrupados logicamente, hierarquia clara e fluxo intuitivo.

C

Consistência

Usar os mesmos símbolos, cores e padrões em todo o modelo.

C

Compreensão

O cliente (não técnico) também deve conseguir entender o que foi modelado.

P

Padronização

Seguir padrões reconhecidos (UML, BPMN) facilita o trabalho em equipe.

M

Manutenção

Um bom modelo facilita atualizar e comunicar mudanças no sistema.

Modelo bom vs. ruim

✅ Bom modelo

  • • Legível por dev e cliente
  • • Usa padrão UML consistente
  • • Atualizado com o projeto
  • • Descreve o que é essencial

❌ Modelo problemático

  • • Só o autor entende
  • • Mistura notações diferentes
  • • Desatualizado após sprint 1
  • • Modela detalhes desnecessários
🏆 Um bom modelo é suficientemente simples para comunicar e suficientemente detalhado para construir.

Atividade de Fixação

Prática

🏥 Situação: Sistema de Agendamento Médico

Uma clínica médica deseja substituir seu caderno de papel por um sistema digital de agendamentos. O sistema deve permitir que pacientes agendem consultas pelo celular, integrando com o sistema de prontuário já existente e enviando confirmações por WhatsApp via API.

Responda em equipe:

1.
Como você demonstraria iniciativa ao perceber que o sistema antigo gera erros de duplo agendamento? O que você faria antes de ser pedido?
2.
Liste 3 princípios de UX que você aplicaria na tela de agendamento para garantir boa experiência para o paciente idoso.
3.
Identifique 2 pontos de integração (APIs) necessários e descreva o que cada uma troca entre os sistemas.
4.
Escolha 2 tipos de modelagem que você usaria para documentar o sistema e justifique a escolha.
5.
Desenhe (ou descreva) um Diagrama de Caso de Uso simplificado com pelo menos 3 atores e 4 funcionalidades.
